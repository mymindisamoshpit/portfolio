# Тест-кейсы драйвера фискального регистратора

Ниже представлены основные тест-кейсы, разработанные и выполненные на стенде в рамках проверки работоспособности драйвера.

## Т1: Проверка открытия смены
- **Приоритет:** Высокий
- **Предпосылки:** Фискальный регистратор подключен и включен
- **Шаги:**
  1. Создать экземпляр класса `Tfr`
  2. Вызвать метод `CreateFR`
  3. Вызвать метод `SetConnectionParams`
  4. Вызвать метод `OpenShift`
  5. Проверить результат операции
- **Тестовые данные:** Параметры из `config.json` (connection_type=6, ip_address=192.168.1.100, tcp_port=7778, timeout=1000)
- **Ожидаемый результат:** Метод завершается без ошибок, код результата равен 0, смена открыта
- **Фактический результат:** Соответствует ожидаемому
- **Статус:** Пройдено

## Т2: Проверка печати фискального чека
- **Приоритет:** Высокий
- **Предпосылки:** Смена открыта, в фискальном регистраторе есть бумага
- **Шаги:**
  1. Инициализировать драйвер и установить соединение
  2. Открыть смену
  3. Сформировать чек с одной позицией (наименование "Товар 1", количество 1, цена 100 руб., НДС 20%, оплата наличными)
  4. Вызвать метод `ProcessCheck`
  5. Проверить наличие напечатанного чека
- **Ожидаемый результат:** Чек печатается, код результата равен 0, чек содержит корректные данные
- **Фактический результат:** Соответствует ожидаемому
- **Статус:** Пройдено

## Т3: Проверка закрытия смены
- **Приоритет:** Высокий
- **Предпосылки:** Смена открыта, пробит хотя бы один чек
- **Шаги:**
  1. Инициализировать драйвер
  2. Вызвать метод `CloseShift`
  3. Проверить печать Z-отчета
- **Ожидаемый результат:** Z-отчет печатается, смена закрывается, код результата равен 0
- **Фактический результат:** Соответствует ожидаемому
- **Статус:** Пройдено

## Т4: Проверка обработки ошибки при отсутствии связи с ФР
- **Приоритет:** Средний
- **Предпосылки:** Фискальный регистратор физически отключен или недоступен по сети
- **Шаги:**
  1. Отключить кабель от фискального регистратора
  2. Создать экземпляр класса `Tfr`
  3. Вызвать метод `CheckFRState`
  4. Проверить код ошибки
- **Ожидаемый результат:** Метод возвращает код ошибки, отличный от 0, описание ошибки сохраняется в лог
- **Фактический результат:** Соответствует ожидаемому
- **Статус:** Пройдено
